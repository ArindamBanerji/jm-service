# Astra sweep 1 — RGI Data Label Judgment

**Date** 2026-11-18 · **Scope** LBL-P2, LBL-P3, LBL-PH0  
**Verdict: BLOCKED before P1.** The shipped modules agree on four factor IDs, but the same IDs would carry different evidence under the v6 core loop. The public report also rejects the documented input format.

**Summary:** 6 blockers, 5 warnings, 3 notes. Counts refer to the numbered findings below. Blockers affect shared contracts, startup, or the correctness of customer-facing results. Recommendations are proposed changes for human review.

### Blockers

| ID | Finding and affected files | Recommended fix |
|---|---|---|
| B1 | **Difficulty and schema values would change meaning across engine versions.** In the v6 design §3 and its Factor Display Contract, 0.15 means simple and 0.80 means difficult. The default is normalized entropy of a class distribution, zero for one class and 0.5 when unavailable. In `labeling_factors.py`, agreement within three confidence bands yields 1 (easy), including empty and single-score inputs. This computes ease from a different input. The design's name, formula and anchors agree. Schema complexity also differs. Five flat classes yield 0.20 in v6 and about 0.194 in P3, while 20 flat classes yield 0.80 versus about 0.417. P3 includes relation count and accepts missing depth. | Keep the canonical difficulty ID and implement its registered high-harder proxy and defaults. Use v6's active-class/depth formula. If the ease proxy is retained, give it a distinct versioned definition. Version or rebuild any previously learned geometry before mixing values. |
| B2 | **Calibration reads a different history contract.** §3 specifies prior qualified `annotator_correct` records for the same annotator, category and epoch, excluding imports. `labeling_factors.py` takes boolean `outcome_correct`, filters only category and takes the last 50 input rows. A v6 log yields the neutral default. A descending query with more than 50 rows selects older observations. With 1–4 valid outcomes P3 returns 0.5 even when all are correct. | Specify who filters and orders the log, implement a typed adapter for the latest 50 eligible records, exclude the current label, and return the mean whenever evidence exists. Test multiple annotators and epochs. |
| B3 | **The documented CSV fails at the public endpoint.** §19D requires `label_id, category, proposed_action, actual_action, verified` plus at least two `factor_*` columns. A 300-row v6 upload returned 422 for missing `verified_outcome`. In `label_health/ingest.py` and `api.py`, optional `action` and nullable `verified_outcome` replace those fields. Optional `existing_label` is not reserved. Every numeric nonreserved column becomes a factor in header order, with its prefix intact. Only unprefixed, identically spelled CSV IDs match P3 directly. The 200-row and two-factor minima agree. The 50-verified minimum only warns, deliberately following the PH0 acceptance test. Category/action bounds, delimiter exclusion, strict verification/action pairing and mixed/duplicate header rejection are missing. | Adopt a versioned §19D parser, strip factor prefixes, preserve IDs as strings and validate headers before pandas can rename duplicates or coerce IDs. Enforce 1–20 categories, 2–10 actions and the verification threshold. Explicitly version any retained legacy schema. |
| B4 | **Replay can fail after validation or report the wrong evidence.** In `ingest.py`, one observed action is replaced by approve/reject. In `analyze.py`, the original action is still passed to learn. A valid legacy upload with every action set to review returned HTTP 500. Missing actions are inferred from correctness and the first two actions, whose order can depend on the file. Sorting the optional timestamp also changes §19D's CSV replay order. The report lacks a separate simulated routing result. | Validate a single action vocabulary before replay, retain row order, learn the supplied actual action and calculate label correctness from proposed/actual agreement. Expose simulated recommendation agreement separately. Return validation errors for unsupported inputs. |
| B5 | **JSON consumers and cost estimates cannot rely on §19D.** `analyze.py`, `api.py` and `render.py` emit nested metadata, category_risks, separate silent_risks and nullable annotator_profiles. v6 expects report_version, top-level counts, categories with advisory status/tier/silent_risk, and an annotators array. The API ignores the optional monthly volume and unit cost. Zero verified rows returned 200, accuracy 0 and $250,000 projected cost from assumed 10K labels at $25. A category with no verified evidence likewise appears 0% accurate. | Return the versioned response, use null for undefined accuracy and missing cost inputs, expose sample count and assumptions, and calculate annual cost from supplied monthly volume × unit cost × verified error rate × 12. Render unavailable values explicitly. |
| B6 | **The service image omits the router it imports.** `jm_service.py` imports `label_health.api` unconditionally. The current `Dockerfile` copies root `*.py` only. In a clean image built from that recipe, the application package is missing at startup. Local router tests use the source tree. This is a packaging finding from inspection, not a container build result. | Include the package in the image, then smoke-test the application import, health route and a report upload from the built image. |

### Warnings

| ID | Finding and affected files | Recommended fix |
|---|---|---|
| W1 | **FactorArray is compatible with one scoring path.** `compute_factor_array()` is annotated as `list[float]`. Its actual subclass implements `.get(name, 0.5)`, exactly the lookup used by `jm_core.score()`. A direct call worked. The cast in `test_labeling_factors.py` changes only static typing. Readonly scoring calls `.items()` and raised AttributeError for the same object. JSON serialization yields an array, while the service request requires an object. | Keep ordered arrays for vector consumers and construct a real typed factor dictionary from display rows at engine and HTTP boundaries. Test parity across score, readonly and serialized requests. |
| W2 | **Conservation, autonomy and annotator profiles are incomplete.** `analyze.py` correctly creates an independent `ConservationState` per category, updates it from verified label correctness and calls `check_gate(1)`. This projects label quality independently of the core's global recommendation-agreement history. It discards the pause reason and assigns three colors from count and all-time accuracy independently of the gate. §6/§19D specify four illustrative tiers and gate constraints. Annotator profiles are grouped means, including thin groups, without separate engines or dual-Welford summaries. `render.py` omits per-category annotator accuracy. | Preserve the gate reason, apply the versioned §6 tier policy to report evidence, keep import authority advisory, and implement evidence-aware annotator profiles with the promised category breakdown. |
| W3 | **HTML has no reusable PDF download.** `api.py` offers a second upload at POST report/pdf. `render.py` supplies no report ID or relative download link. §19D requires a capability GET for the same generated PDF, 24-hour expiry and 404 after expiry. A 10 MiB input limit exists, but there is no report CPU/time or output-size limit. Synchronous analysis and rendering run in async handlers. The recorded Windows fallback emits plain text through ReportLab, losing the styled table layout. | Generate and serve one bounded private artifact per report, link it from HTML, and check expiry, response headers, size, timing and PDF readability in the deployment environment. |
| W4 | **A structurally valid display row can misrepresent evidence.** `FactorDisplay` has all six requested keys, but `labeling_factors.py` cannot distinguish a default 0.5 from an observed 0.5 in its output. Missing model confidence has no supported entry point. Empty item scores yield certainty of ease, and a single nonfinite or out-of-range score bypasses validation. The design places the display subsection under §3, despite the prompt's §5.1 reference. | Carry default provenance and factor-contract version alongside the six display fields. Validate inputs before single-value shortcuts and test missing confidence versus observed 0.5. |
| W5 | **The acceptance suites leave boundary failures undetected.** `test_label_health.py` checks a short CSV as its only API failure and mounts an isolated router. No committed API cases cover malformed quotes, invalid bytes, empty uploads, non-CSV content, duplicate headers, size overflow or the HTML route. Media type is not checked. A float all-NaN column returned 422 in the sweep, one category succeeded, and an all-empty action column silently fell back to defaults. None of those cases is asserted. Replay order, partial verification, category gate transitions, exact profile values, positive reverification counts, annual cost, and HTML/PDF data parity lack assertions. With two actions the maximum softmax probability is always ≥0.5, so the shipped strict threshold always counts zero. `test_labeling_factors.py` checks the cast path but misses history ordering, invalid singleton scores and missing defaults. | Add contract cases at the real app and engine boundaries, including a three-action ambiguous probe, exact category/annotator outcomes, 49/50 verified, valid single category, malformed inputs and a full HTML-to-PDF retrieval. Verify numeric output as well as status codes. |

### Notes

| ID | Observation and affected files | Recommended follow-up |
|---|---|---|
| N1 | **Canonical order and record shape agree.** `labeling_factors.py` produces model_confidence, annotator_calibration, item_difficulty, schema_complexity in design order. Its TypedDict requires factor, display_name, value, low_label, high_label and description. | Reuse these IDs when normalizing CSV headers and keep version/provenance metadata beside the display contract. |
| N2 | **Core call signatures and inversion keys agree.** `analyze.py` scores each verified row, supplies decision_id, actual_action, confirmed, outcome_correct and track_outcome to learn, then batch-scores all rows with dictionaries containing factors and category. `jm_core.py` returns a populated inversion dictionary or None. Analysis passes it through. `render.py` skips None or an empty dictionary and consumes trusted_factor and actual_signal_factor when populated. None profiles are safe. Other numeric fields formatted as percentages/currency currently require numbers. The inversion test is deterministic: factor_0 is constant, factor_1 has a 0.8 outcome mean gap, and 240 correct/60 incorrect samples exceed thresholds. | Strengthen the fixture assertion with both factor IDs and the gap, and type the report payload so missing keys and nullable metrics are checked. |
| N3 | **Source-tree mounting and dependencies agree.** `jm_service.py` includes the anonymous router once. Its prefix plus route paths give POST /v1/label-health/analyze, /report and /report/pdf under the same prefix, without conflicts with health, register or domain routes. `requirements.txt` lists pandas, WeasyPrint, python-multipart and ReportLab. | Retain the mounted-route and dependency checks when verifying the packaged service in B6. |
