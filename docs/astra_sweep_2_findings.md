## Interface and test notes

**N1 — core types and response serialization.** `labeling_factors.py` produces the six display fields plus required boolean `is_default`. `FactorArray.get` supplies the frozen scorer's named lookup; it lacks the readonly scorer's `.items()`. The live router passes a real `dict[str, float]`. Report replay passes a real dict to score and a list of dictionaries with `category` and `factors` to readonly batch. Core inversion returns a populated dict or None. The report forwards it and HTML handles falsey inversion, missing profiles and null accuracy/cost. Policy returns dataclasses with string enums, serialized via `asdict`; the nested key is `recommended_action_policy`, and the ingest alias is `action_policy`. Recommendation: type the report and tier response boundaries explicitly. Bare dicts/Any limit what the successful mypy check establishes.

**N2 — transactional wiring and packaging.** Repository reads and writes reference existing ORM columns. Domain config, core state and score-time factors round-trip as JSON. Engine updates guard the loaded version in SQL; the stale-version unit test passes. Constraints cover domain/label, domain/annotator and a partial unique project-engine index. Ingest writes score and engine together, then evaluates policy. Verify locks the label, reconstructs a pending core decision from its durable row, learns using action agreement and supplied outcome separately, then writes verification and state. The request session commits on success and rolls back on error. Pending filters by domain, unverified state and optional category, ordering by ascending confidence with tie-breakers and a 1–200 limit. Mounted routes have distinct paths. Requirements cover FastAPI, multipart, pandas, both PDF renderers, SQLAlchemy and both async DB drivers; NumPy is imported directly and supplied transitively by pandas. Recommendation: retain these contracts, test two real PostgreSQL sessions racing on one verification and on first writes, and verify recovery after conflicts. SQLite and sequential stale-version tests do not exercise PostgreSQL locking.

**N3 — same scorer, different evidence.** §8's hosted and ephemeral paths use the same frozen geometry. In a cold-start probe with identical numeric factors, live ingest returned approve at 0.5. A valid v6 upload with reject as its first observed action replayed reject at 0.5. Ties choose the first configured action. V6 CSV strips factor prefixes, legacy CSV retains names, and live ingest takes keys literally. The report fits one ephemeral engine in replay order and rescores all rows after training. Live scores reflect the persisted project or annotator state at the instant of ingest. Recommendation: test per-action parity with identical names, action order, scope, state and event sequence; document when a comparison has different histories. Report output exposes no per-item score map for a direct HTTP comparison.
