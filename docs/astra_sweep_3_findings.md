### Deployment and Label Studio checks

Docker builds frontend/package-lock.json with Node 22 Alpine and copies dist into Python 3.11 slim alongside root Python, db/, label_health/ and the executable LF entrypoint. The lock lists Linux musl bindings. Compose gates jm-api on pg_isready for postgres:17-alpine and supplies the asyncpg URL with host postgres, persistent pgdata and /data. Entrypoint uses set -eu, migrates then execs uvicorn on PORT or 8000. Railway points at /v1/health. StaticFiles is mounted last. API-first route order worked in the browser smoke. The runtime dependency list covers the service imports, both SQL drivers, multipart, pandas/NumPy and both PDF backends. The image includes test tools and root test scripts, runs as root, and depends on system libraries for faithful PDF rendering. Railway requires a provisioned DB, a SQLAlchemy async-compatible URL and persistent storage for legacy state and LS mappings. Test the image with the actual provider URL, restart and native PDF.

LS predict uses shared _ingest for first scoring. With identical config, factors, scope and history the stored raw scores use the same scorer. **Returned scores differ** outside eligibility: a raw 0.50 becomes 0.245 through the 0.49 multiplier. Repeat predict reuses the stored score and rechecks current eligibility. Results contain an empty annotation array. Initial verified webhook events use the same repository.verify_and_learn transaction as the labeling route. They select a project engine and set completed_by attribution after learning. No ground truth leaves the item pending. UPDATE uses the separate replay in R4. Config is read from disk on use and written via same-directory atomic replace. It survives process restart on persistent storage, with a process-local writer lock. On PostgreSQL the mounted setup endpoint returned 401 for missing token, 401 for incorrect token and 200 for the valid fixture token. Missing server secret yields 503 in code. Health is public. Shared-token authentication does not validate time, event uniqueness or project-specific authorization.

### Recommended build sequence and release boundary

1. Fix review identity and stale submission immediately. Add scoped item evidence and a browser regression covering switch, refresh and delayed verification. In parallel, define tenant ownership and migrate the existing rows before admitting customer data.
2. Introduce durable event/revision identities, source/epoch columns, migrations and a deterministic replay contract. Exercise multi-annotator revisions and concurrent verification on PostgreSQL. Bind connector credentials to project ownership.
3. Complete independent adjudication, schema/model holds and the two-scope policy. Keep platform automation disabled until raw action, confidence, fresh evidence and the applicable quality floor pass together. Run a real Label Studio project through this gate.
4. Gate deployment on clean-image startup, provider URL, persistent volume recovery, upgrade rehearsal, native PDF output and bounded concurrent report/ingest workloads. Complete cursor queue, escalation, resumable batches and category detail for the first review customer.
5. Complete the report artifact and cost contract, paired chart data and held-out evaluation before claiming precision or improvement. Add metering/billing before charging by tier. Schedule RLHF, secondary connectors and competitive features after their shared dependencies.

**Can ship now:** an internal single-domain, human-reviewed demonstration using non-sensitive data, the standalone CSV report with disclosed assumptions, and the frozen engine/build artifacts. The observed browser loop supports this scope. Public durable labeling, external automatic acceptance, production revisions and paid-tier commitments need the work above. Anonymous report availability at scale still requires the artifact, load and image checks.

**Summary:** four release blockers (R1–R4), five warnings and 34 inventory rows (5 shipped, 18 partial, 11 not built). First close domain ownership and review-target integrity, then validate replay and automatic eligibility before enabling the hosted connector.
